## Branching

- `develop` is the daily working branch (development, engineering, cybersecurity). Direct commits are allowed and every push runs the full `ui-stack` CI.
- `main` is the release branch and the repository default. It only receives merges via PR `develop → main` with green CI. There is no active Lovable connection — this project is a source-code export for engineering work; if a connection is established later, `main` is the branch to connect.
- Never force-push, rebase, or amend commits already pushed to any published branch.
- Formal branch protection is pending GitHub Pro or a public repository; see `docs/adr/ADR-017-branching-strategy.md`.
- Whenever `main` moves ahead of `develop` (release PRs, bot PRs merged straight to `main`), merge `main` back into `develop` immediately. A `develop` that falls behind the release line redeploys stale configuration and hides drift — PR #42's Vercel fix only turned `develop` deployments green after the back-merge.

## Local quality gate (definition of done)

- Before pushing, run `npm run check` and keep it green. It chains `m02:lockfile-guard`, `m02:work-package-guard`, `m02:debts-guard`, `m02:temporal-guard`, `m02:boundaries`, `m02:secrets-audit`, `m02:seal-dts:check`, `m02:matrix:check`, `check:ui-stack`, `check:no-supabase-runtime`, `format:check`, `lint`, `typecheck`, `test`, `build`, and `check:bundle`.
- The CI `verify` job (`.github/workflows/ui-stack.yml`) runs **14 dos 16** scripts da cadeia `check` como passos diretos, mais `npm audit --audit-level=high`, e — **em tiers** — `db:test`/`db:check` (diff de banco) e Playwright e2e (chromium+mobile no push, +firefox+webkit no PR); a matriz completa roda em **todo PR** e no `workflow_dispatch`. A push that skips the local gate wastes a CI cycle; treat any red as debt, never as noise.

  **Cobertura de guardas, por pipeline (não é "os mesmos gates" — é esta tabela; DBT-19):**

  | gate / guarda | `check` local | heavy `verify` | light `ci-light` |
  | --- | --- | --- | --- |
  | `m02:work-package-guard`, `m02:debts-guard`, `m02:temporal-guard` | ✔ | ✔ (passo direto) | ✔ (passo direto) |
  | `m02:lockfile-guard` | ✔ | ✘ — o *drift* é pego por `npm ci --ignore-scripts` (`EUSAGE`); a asserção do pin de `drizzle-kit` **não** roda em push de código | ✔ (passo direto) |
  | `m02:seal-dts:check` | ✔ | ✘ como passo — coberto **por equivalente** dentro de `npm run test` (`src/test/m02-seal.test.ts` executa `generate-seal-dts.mjs --check` e falha por byte-diff, com controle negativo) | ✘ |
  | `m02:matrix:check`, `check:ui-stack`, `check:no-supabase-runtime`, `format:check`, `lint`, `typecheck`, `test`, `build`, `check:bundle` | ✔ | ✔ (passo direto) | ✘ (só `format:check` nos arquivos alterados) |
  | `m02:secrets-audit` | ✔ | ✔ (passo direto) | ✔ (passo direto) — **encadeado em 2026-09-23** (commit `c7e6a55`): até então um push **só de código** nunca o executava |
  | `m02:boundaries` | ✔ | ✔ (passo direto) | ✘ — a light só dispara quando **todos** os arquivos alterados estão sob `docs/evidence/**`, e a matriz (`docs/specs/M-02/`) não muda nesse caso. **Encadeado em 2026-09-23** (commit `c7e6a55`): até então não estava ligado a gate nenhum |
  | `m02:state:check` | ✘ | ✘ | ✘ — é passo do protocolo de boot, roda à mão |

  A tabela é o contrato: um gate que aparece como ✔ tem de estar no encadeamento do pipeline citado, e um ✘ **nomeado** (com o equivalente, quando existe) é limite declarado, não lacuna esquecida.
- **Cota de Actions:** o job pesado custa **~9,7 min de runner por execução real** (média de 8 execuções verdes medidas: 497-605 s; os 5 runs bloqueados de 3-6 s da cota **não** entram na conta — média contaminada por eles daria ~6 min, que é o número que estava aqui antes), e um push em rajada cria uma execução por commit — sem cobrança por caminho, um dia de trabalho consome a cota do mês. Por isso o `verify` roda em **tiers**, e o `concurrency` cancela o run superseded da mesma ref. **Nenhum teste foi removido, nenhuma regra afrouxada, nenhum orçamento renegociado:** o que mudou foi *onde* cada verificação roda.
- **Two CI pipelines, selected by changed paths:**
  - **Heavy — `UI stack`** (`.github/workflows/ui-stack.yml`): every pull request, plus pushes to `main`/`develop` whose changed files are **not** all under `docs/evidence/**` (`paths-ignore`). Também aceita `workflow_dispatch` para um run completo sob demanda.
  - **Tiers dentro do `verify`** (escopo por `git diff`, fail-closed — base desconhecida ⇒ tudo roda): **sempre que a heavy é disparada** rodam as guardas, `format:check`, `lint`, `typecheck`, `npm run test`, `build`, `check:bundle` e o audit (o *disparo* é que é filtrado por caminho — docs-only vai para a light); **`db:test`/`db:check`** só quando o diff toca `drizzle/`, `src/db/`, `src/server/repositories/`, `src/server/services/`, `scripts/db/` ou os manifests, e o pulo é **visível** (`::notice`), nunca silencioso; **e2e** roda **chromium+mobile** em push e **firefox+webkit+mobile** em PR e no dispatch. A fronteira de release é o **PR**: todo PR roda a matriz completa.
  - **Light — `CI light (docs/evidence)`** (`.github/workflows/ci-light.yml`): pushes and pull requests whose changed files are **all** under `docs/evidence/**` — runs `scripts/m02-lockfile-guard.mjs`, `scripts/m02-work-package-guard.mjs`, `scripts/m02-debts-guard.mjs`, `scripts/m02-temporal-guard.mjs`, `scripts/m02-secrets-audit.ts` and `prettier --check` on the changed files only. The temporal guard is the **one step without the scope `if:`** — by design: its surface includes the root ledger and the human queue, so a mixed push that no-ops the other steps still has to keep the live prose honest. It installs **no** dependencies: the scripts import node built-ins only. A mixed push (code + docs) belongs to the heavy pipeline; the light job's scope guard exits without work instead of failing. **Coverage guarantee:** the two filters are exhaustive for pushes to `main`/`develop` — docs-only runs the light with the contract guard, any other change (including a mixed push, which triggers both with the light no-opping) runs the heavy `verify`, and a code-only push never triggers the light at all. The formatter is resolved from the **lockfile** (`package-lock.json`), never from the `package.json` range: a caret range resolved to a different release than `npm ci` installs, so the light pipeline drifted from `npm run format:check` and failed docs-only pushes the repo's own gate accepted.
  - Neither filter applies to code: anything under `src/**`, `scripts/**`, `.github/**` or the manifests always goes through the heavy pipeline.
- **Protocolo de bloqueio de CI (precondição de ambiente externo, item 17 estendido):** quando a plataforma recusar iniciar jobs (cota/billing, anotação do check-run citando *spending limit*), o CI é uma **precondição não satisfeita**, não um veredito — e vale: (a) o `npm run check` local é o **fallback declarado**; (b) todo land durante o bloqueio entra no **ledger de janela sem verificação** com os SHAs enumerados; (c) **nenhum selo cita run inexistente** — selo com `run@sha` só depois de existir run; (d) o primeiro push pós-desbloqueio roda a **varredura de verificação** da janela antes de qualquer land novo; (e) manter **alertas de spending** (50/75/90/100%) ligados, para o esgotamento se anunciar antes de bloquear. Registrar a causa pela anotação da plataforma, nunca por inferência.
- **Run `cancelled` não é evidência** — nem verde nem vermelho — para a regra `run@sha`; a delegação por run no-op continua exigindo **≥ 1 check aplicável** no mesmo commit.
- Never claim work is done with a red gate, and never delete, skip, or loosen a test, lint rule, or budget to force a green.

## Dependency discipline

- Every `package.json` change ships with a synchronized `package-lock.json` in the same commit. CI installs with `npm ci --ignore-scripts` and hard-fails (`EUSAGE`) on lockfile drift — this exact mismatch broke PR #42's install step.
- Do not assume a library is available because it is common: confirm it in `package.json`/lockfile first, and match the version and idiom already in use.

## Local database

- `npm run db:up` / `npm run db:down` manage a Docker `postgres:17-alpine` container that mirrors CI (`docker-compose.yml`); see `docs/runbooks/postgres-local-docker.md`.
- `npm run db:test` is self-contained against that container with `DATABASE_URL`/`DATABASE_ADMIN_URL` pointing at `127.0.0.1:5432` and `DATABASE_DRIVER=node-postgres`.
- Author migrations with `npm run db:generate` (drizzle-kit), validate them with `npm run db:check`, and exercise them with `npm run db:test` — always against the local container.
- Classifique toda migration no registry sidecar (`scripts/db/migration-classes.ts`) e valide com `npm run db:classify:check` (prepend do `db:test`); a política expand/contract está em `docs/runbooks/migration-safety.md`.
- `scripts/env-guard.mjs` runs as a pre-hook on dev/test/build/db commands and denies remote (Neon) targets. Never bypass it with ambient environment variables; explicit overrides may only point at `127.0.0.1`.

## Security baseline

- The Content Security Policy in `src/start.ts` is strict (`script-src 'self'`). Never add `'unsafe-inline'` or new hosts without first verifying the package's actual runtime behavior in its published dist and documenting that evidence in the PR. (PR #42 lesson: `@vercel/analytics` injects an external same-origin script via DOM — the strict CSP already covered it, and the proposed relaxation was reverted.)
- Keep `m02:secrets-audit`, `m02:boundaries`, and the env guard green; they are contract, not decoration. **Encadeados em 2026-09-23** (commit `c7e6a55`); **`DBT-19` segue ABERTA no registry** — a condição de fechamento exige, além do caso negativo, que **esta tabela bata com os YAMLs por asserção de teste**, e essa asserção ainda não existe (`m02-ci-coverage.test.ts` lê só os dois YAMLs; nenhum teste pinna a cadeia `check`). Declarar fechado sem a asserção seria a mesma cobertura aparente que a dívida denuncia. Até 2026-09-23 `m02:secrets-audit` rodava só na light e `m02:boundaries` em gate nenhum — um push só de código nunca executava nenhum dos dois. Ambos entraram no encadeamento do `check` e como passos diretos do `verify` (≈2,0 s medidos), e a **primeira** correção de então foi de fundo: o `m02:secrets-audit` **detectava** literais de segredo (`possible_secret_literals`) e ainda assim saía `0`, porque o veredicto olhava apenas a cobertura — encadeá-lo assim daria cobertura de segredo **aparente**. O exit code passou a distinguir `2` (precondição/cobertura incompleta) de `1` (literal detectado), com caso negativo versionado em `src/test/m02-boundary-gate.test.ts`. Verde medido à mão em 2026-09-22: `m02:boundaries` → *"BFF boundary is clean"*. Declarar contrato e não executá-lo é a lacuna, não a guarda.
- Never commit secrets: `.env` stays local and gitignored; deployments read from the platform's env store.

## Work packages (contrato de prova)

- **Guardas derivadas (WP-R7):** `scripts/m02-temporal-guard.mjs` percorre a **superfície viva** de prosa — §1 do `PROGRESS.md`, último bloco do `EXECUTION-STATE-PROGRAM.md` e o `REGISTRO-H.md` **menos** a seção `## Fechados` (a fila aberta e o que vem depois dela) — e reprova (a) toda âncora em crases que seja hex de 7–40 **com ao menos uma letra** (id de run todo-decimal não é âncora) ou par `sha@run` com o sha à esquerda, quando **não resolve** como objeto do git (a convenção do repo carimba **árvore**, não commit; sufixo `…`/`...` é prefixo), e (b) toda data válida que venha até 100 caracteres **depois** de um **verbo** de prazo (`\bcaduca\b`, `\bexpira\b`, `\bvence\b`, `\bdeadline\b`) e esteja no passado; data inválida (rollover) também reprova. O substantivo `prazo` **não** é marcador (é palavra-tema), e a isenção de errata é **por data** (janela de ±45 caracteres com `ERRATA|histórico|anterior|desatualizad|corrigid`) — o repo manda escrever errata, e isentar a linha inteira esconderia o prazo vivo que ela carrega junto. O journal append-only fica fora por construção; **limite declarado:** as intenções órfãs (`▶` sem `✔`/`✘`) vivem nele e **não** são cobertas. Exit `2` é precondição (sem git, superfície ausente, recorte vazio, cabeçalho de fronteira ausente), distinto do `1` de violação. Roda em `check`, no `verify` do `ui-stack` e na light — na light é o **único passo sem o `if:` de escopo**, por desenho. Os **tiers do `verify`** são vigiados por `src/test/m02-ci-tiers.test.ts`, que **executa o script de escopo real extraído do YAML** (com as expressões `github.*` substituídas): polaridade fail-closed (`!= 'false'`, nunca `== 'true'`), base desconhecida e `workflow_dispatch` emitindo **os dois** outputs, e `concurrency` que não cancela `main`. `scripts/m02-seal.d.mts` é **gerado** por `scripts/generate-seal-dts.mjs` a partir do JSDoc de `scripts/m02-seal.mjs` — a fonte dos tipos é o módulo, e editar a declaração à mão reprova em `npm run m02:seal-dts:check` (encadeado no `check`) e no teste de geração.
- **Dívidas:** toda dívida declarada (defeito novo, limite latente, higiene ou conformidade) entra em `docs/evidence/agent-state/DEBTS.md` com `id · origem · classe · severidade · closure test · evidência · status`, validado por `m02:debts-guard` (registry vazio, coluna ausente, valor degenerado, ID duplicado e closure test ausente com status ≠ `NS` reprovam — nas duas direções). O registry vive sob `docs/evidence/**` (coberto pela light) e o guard roda em `check`, no `verify` do `ui-stack` e no `ci-light`.
- Todo work package segue o template `docs/evidence/_templates/work-package.md`: `SPEC.md` (S1) + `README.md`/selo (S5) + `captures/*.txt` + `MANIFEST.sha256`, com o **checklist anti-vacuoso demonstrado item a item** antes do S6 adversarial — 17 itens: controle negativo, fronteira nas duas direções, identidade (não cardinalidade), proibido exit-code-only, proibido sleep fixo, sem valor degenerado na identidade, precondição de estado compartilhado, sentinela real por cenário, fingerprint de revisão, `checked === discovered` (descoberta vazia reprova), S6 de contexto limpo, falha alta/fail-closed, isolamento de bancada assertado, todo check impresso com gate+captura, **run de CI atado ao commit selado** (`headSha` igual/descendente e **≥ 1 check aplicável**; run no-op só como delegação ao heavy), **descoberta multi-sítio** (sítios enumerados por catálogo/grep, sítio novo falha por default) e **precondição de estado ambiente** (a ferramenta de evidência declara e verifica em runtime as próprias precondições — worktree limpo fora do selo, profundidade de clone, deps, rede — falhando **fechado** com `exit 2` de precondição, distinto do `exit 1` de veredito; teste que dependa de estado de repo constrói fixture própria). O `README` registra a **auto-verificação pré-S6** e o KPI `capturados pelo autor / total` — o checklist mede prevenção, não só detecção. O selo é gerado/conferido preferencialmente por `scripts/m02-seal.mjs` (não-vacuidade, `D≠L`, sha256, `SPEC`/`README`, ancestralidade offline por `merge-base`, precondição de worktree e taxonomia provado × indeterminável).
- **Taxonomia de veredicto:** **CORR** = *claim* corrigida pelo S6; **N** = defeito novo encontrado (pode existir com `0 CORR`); "correções forçadas" = CORR + N corrigidos. Os dois números vão **nomeados** no journal — contar só CORR subnotifica o custo do S6. Os bounds do SDD (`bound 2`) limitam **rodadas de correção de um WP**, não a quantidade de claims corrigidas num veredicto.
- O S6 é lane adversarial de **contexto limpo** com `0 REJECTED`; `UNVERIFIABLE` exige declaração no selo e **não** conta como verificado; os N **corrigidos** ficam na §7 do selo e os **declarados** na §Riscos, nunca omitidos. `UNVERIFIABLE` é reservado a **inverificabilidade de princípio** (estado externo inalcançável): ausência verificável por grep/introspecção é `REJECTED` ou defeito declarado, nunca `U`.
- **Elegibilidade no placar (187 itens):** a unidade é o **sub-item** — `15` são sete linhas, `25` são sete; **cluster não é unidade de placar**. Promoção a `DONE` exige a **conjunção** de todos os sub-itens exigidos (maioria, "quase tudo" ou "o principal" não promovem); `PARTIAL` exige **delta nomeado** ("falta X") e sem ele é inválido; o denominador é **fixo em 187** (item inaplicável vira `NA` dentro dos 187, nunca sai da conta); a fórmula é **congelada** em `(D + ½·P)/187`; e o **escritor do placar é o MAESTRO** — work package mede e **propõe**, nunca promove. Evidência de classe é **comando pré-registrado antes da medição**, e ausência **verificável** (grep, `ls`, API de estado de recurso) é `NS`, nunca `UNVERIFIABLE` — `U` é reservado a inverificabilidade **de princípio**.
- **Calibração do S6:** os probes plantados de `REJECTED`/`UNVERIFIABLE` rodam em **série separada** dos reviews reais (periodicamente ou a cada troca de revisor), para calibrar a lane sem contaminar a evidência de um WP; a densidade de achados por WP vai para o journal e é lida como série, não como ponto.

## Session boot and progress journal

- `docs/evidence/agent-state/PROGRESS.md` is the **session handoff**: one file, pointers only (paths, SHAs, timestamps, env **names**), never secret values and never long content. A new model reads it and resumes without agent memory.
- **Boot protocol (~30 s), in this order:** (1) read `PROGRESS.md`; (2) verify the parent-pinned marker in `EXECUTION-STATE-PROGRAM.md` (`npm run m02:state:check`); (3) check watchers and their marker files' last signal; (4) **reconcile** the world first (git refs, artifacts, deployments) — never re-execute blindly; (5) resume from the declared phase.
- **Write protocol:** record intent (`▶`) **before** any mutation and result (`✔`/`✘`) **after**, append-only. An orphan intent means the next boot must reconcile before acting.
- **Milestones:** commit the journal at every phase boundary; the maximum acceptable loss is re-executing from the last milestone (declared, never implicit).
- **Agent memory is an invalidatable cache:** nothing that belongs in an artifact or in the journal is written to agent memory — journal + ledger are the source of truth. Memory carries at most a boot index pointing here.

## Commits

- Conventional Commits in English (`fix(ci):`, `docs(evidence):`, `chore(format):`). The message states the root cause, not the symptom.

## Long-horizon maintenance

- Keep `develop` green — a broken daily branch compounds into every PR cut from it.
- Debug systematically: reproduce → gather evidence → form one hypothesis → apply one fix → verify. No "while I'm here" changes bundled into a fix.
- Bundle budgets (`check:bundle`) and e2e hygiene (`test:e2e:hygiene`) are contracts; renegotiate them only through an explicit ADR, never silently.
- `npm run check` runs `m02:matrix:check`: a change under `src/**` that moves any generated counter (`transactionSites`, `directDatabaseFiles`, …) fails the gate until you run `npm run m02:matrix:generate` and review the diff. The generated `docs/specs/M-02/matrix*.yaml` is the record; never hand-edit it.
