# M02-D-007 — Emenda GAP-DOC: sucedente de Realtime não especificado

- **Data:** 2026-09-05 · **Tipo:** GAP-DOC (emenda de spec, RFC curta) · **Estado:** PROPOSTA
- **Evidência de origem:** `docs/evidence/substrato-2026-09-05/report.md` (auditoria de substrato)

## Fato

Varredura do corpus normativo em 2026-09-05 não encontrou cláusula que defina o
sucedente do Supabase Realtime (WebSocket/SSE/streaming). No código, o chat é
request/response HTTP via server functions (`src/lib/chat.functions.ts`,
`src/lib/chat-execution.server.ts`), sem WS nem SSE (`grep ws|WebSocket|Server|
text/event-stream|EventSource` em `src/` = vazio; nenhum pacote `ws`). O FSM
(WS-06, ADR-026) é homologado em unit tests; chat não tem cobertura E2E; o
wire-level (M-08) permanece `PENDING` (só contrato).

## Decisão

1. Realtime não é requisito do cutover: o comportamento homologado é
   request/response por requisição, sem streaming.
2. Wire-level com mocks continua no escopo de M-08 (cartão RT SA-10), sem
   implicação de calendar para A4/A5/B3.
3. B3 mede latência/erros de request/response; nenhuma métrica de streaming é
   exigida na janela.

## Impacto

- Nenhum requisito novo de infraestrutura ao cutover.
- Expectativa de streaming do Supabase Realtime é formalmente encerrada como
  requisito de migração; ressurgimento exige nova emenda.
